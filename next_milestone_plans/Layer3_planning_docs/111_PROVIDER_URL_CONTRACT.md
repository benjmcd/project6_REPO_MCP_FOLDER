# Layer 3 Provider/Public URL Contract

## Status

Current-main planning/control contract paired with `110_PROVIDER_URL_FREEZE.md`.

This contract defines the minimum admissibility rules for any future provider/public URL lane. It does not allocate a live route, provider adapter, object-store write, ACL change, rendered control, connector dispatch, destination selector, schema/model/migration change, package mutation, qualitative execution, or runtime snapshot write.

## Authority Order

Use this order before auditing or extending provider/public URL behavior:

1. current `project6-origin/main` source and tests;
2. PR `#520` for durable same-origin signed-reference runtime behavior;
3. PR `#514` for rendered same-origin signed-reference UI behavior;
4. PR `#499` for backend/API same-origin signed-reference generation/use;
5. docs `102`/`103` for same-origin signed-reference governance;
6. docs `104`/`105` for rendered same-origin signed-reference UI and deferred gates;
7. docs `106`/`107` and docs `108`/`109` for durable same-origin signed-reference state;
8. `110_PROVIDER_URL_FREEZE.md` and this contract for provider/public URL governance;
9. actual provider/storage configuration and deployment policy, when a future lane names one.

Browser state, copied links, request-local tokens, provider console observations, and operator notes are never sufficient authority for enabling provider/public URL behavior.

## Contract Vocabulary

Reserved labels:

- `provider_public_url_not_admitted`;
- `provider_public_url_generation_blocked`;
- `provider_private_signed_url_candidate`;
- `provider_public_url_candidate`;
- `public_proxy_url_candidate`;
- `provider_public_url_ready`;
- `provider_public_url_delivered`.

These labels are not live states by themselves. They may be used only by a later implementation freeze or progress/control sync to classify the next provider/public URL lane.

## Provider Mode Contract

The first implementation lane must choose exactly one mode:

- `provider_private_signed_url`: a provider-hosted, non-public object URL signed by the provider or storage SDK with short TTL.
- `provider_public_url`: a provider-hosted URL backed by an explicit public ACL or public-read object policy.
- `public_proxy_url`: an application-owned public route/proxy that preserves server-side authority and does not expose provider credentials or raw storage paths.

The chosen mode must be represented in request/response state. The response must not ambiguously call a same-origin signed reference a provider URL.

## Request Contract

A future provider/public URL generation request must be server-authority based and must include, or derive server-side from existing state:

- `session_id`;
- `analysis_plan_id`;
- `pass_run_id`;
- selected-pass associated-cohort method and source authority;
- result-review approval record;
- package-review approval and package ids/hashes;
- handoff/export prepare record;
- APS handoff dispatch record;
- external export/download readiness record;
- same-origin delivery authority;
- durable signed-reference token/receipt/audit basis when the future lane depends on PR `#520` state;
- provider mode selected by the implementation freeze;
- fresh `client_request_id`.

The request must not accept:

- client-supplied `download_url`, `public_url`, `provider_url`, `signed_url`, or `signed_delivery_url`;
- local file paths or provider object paths;
- provider credentials, bucket names, object keys, ACLs, or policy documents from the browser;
- connector ids, destination ids, connector-run ids, or dispatch flags;
- package payload bytes, package mutation fields, source expansion fields, runtime write flags, retry/rerun/recovery/cancel fields, or qualitative execution flags.

Provider/public URL authority must be generated by the server only.

## Response Contract

A future response may expose only response-safe provider/public URL metadata admitted by the implementation freeze:

- URL mode;
- URL value or public proxy route, only when explicitly admitted;
- expiry timestamp or TTL;
- artifact ref/hash/size basis;
- provider/display label that does not leak credentials, local paths, or raw object keys;
- revocation and audit status when implemented;
- disabled downstream flags for connector/destination/generic dispatch unless separately admitted.

The response must not expose:

- provider credentials or signed credential material beyond the intended URL;
- local filesystem paths;
- raw storage object paths when the selected mode is `public_proxy_url`;
- connector targets or destination ids;
- package payload bytes or mutable package content;
- qualitative execution output;
- schema/runtime/source mutation details.

Existing same-origin delivery and same-origin durable signed-reference responses must remain valid and must not start emitting provider/public URL fields unless the request uses the future admitted provider/public URL endpoint or mode.

## Revocation And Expiry Contract

The future lane must define one of these revocation policies before implementation:

- URL expires only through provider TTL and server-side audit records mark it terminal after expiry.
- Server persists a revocation state and denies future public proxy use after revocation.
- Provider ACL/object policy is actively changed to revoke access.

The chosen policy must include:

- who can revoke;
- idempotency key behavior;
- audit event shape;
- stale authority behavior;
- provider failure behavior;
- cleanup and retention expectations.

If revocation cannot be made deterministic for the chosen mode, the first implementation must use the shortest practical TTL and keep the mode operator-confirmed rather than silently enabling shareable links.

## Security Contract

The future lane must fail closed for:

- missing provider configuration;
- missing signing or ACL authority;
- stale associated-cohort delivery authority;
- stale artifact hash/size;
- expired or revoked durable signed-reference state when used as a prerequisite;
- provider errors;
- malformed request fields;
- provider URL leakage into non-admitted responses.

Provider credentials, raw bearer tokens, raw provider signatures, and local paths must not be logged, persisted in audit payloads, or returned in error bodies.

## Test Contract

Minimum future proof:

- focused backend/API tests for disabled-by-default provider/public URL generation;
- missing provider configuration fail-closed tests;
- forbidden client URL/provider/connector/destination fields tests;
- exact authority binding tests across session, plan, pass, package, handoff/export, APS dispatch, readiness, delivery, artifact ref/hash/size, and durable state where applicable;
- expiry, stale authority, wrong artifact, wrong session, malformed request, provider failure, and revocation tests;
- no provider/public URL leakage on existing same-origin delivery and same-origin signed-reference routes;
- no package mutation, connector dispatch, destination selection, schema/runtime/source widening, or qualitative execution side effects;
- headed and headless browser proof if any rendered provider/public URL control is admitted.

## Implementation Stop Conditions

Stop and return to planning if implementation would require:

- supporting multiple provider URL modes in one PR;
- adding connector/destination dispatch;
- making a public ACL change without tracked security review;
- emitting long-lived or non-expiring URLs;
- adding schema/model/migration changes outside a named URL/audit/revocation contract;
- mutating package payloads or APS evidence-bundle artifact bytes;
- introducing qualitative/hybrid/RAG/vector execution;
- changing the PR `#520` durable same-origin signed-reference replay policy without a compatibility freeze.
