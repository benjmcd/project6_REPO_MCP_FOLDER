This freeze selects the next governed SEC HTML/iXBRL product-to-package slice. The future runtime should create a redacted package-review preview over existing statement-candidate product receipts, using package roles that are inspectable by operators and suitable for later package construction and review submission.

The selected runtime must not write output package rows, submit package-review decisions, prepare handoff/export, deliver artifacts, fetch SEC content, reparse HTML/iXBRL, reconstruct raw fact values, resolve taxonomies, call SEC CompanyFacts, process standalone XML/XBRL, broaden parser/source scope, dispatch connectors, write provider objects, run RAG/model logic, activate full mockup behavior, or create browser-held durable authority.

## Runtime Requirements

1. Load and validate an existing downstream product receipt by id plus expected receipt hash.
2. Revalidate the product receipt against statement-classification, fact-authority, fact-material bridge, product manifest, redaction, and downstream-readiness hashes.
3. Build a redacted package-review preview manifest with `canonical_internal`, `review_facing`, and `user_facing` package candidates.
4. Preserve product group order, table-anchor order, unknown diagnostic order, and package-kind order.
5. Reference every statement-candidate group, unknown diagnostic, and table-anchor crosswalk by hash so product evidence is not discarded.
6. Store only append-only preview receipts and redacted status projections: package counts, hashes, review readiness, redaction metadata, and authority hashes.
7. Fail closed on stale authority, missing product/classification/fact/bridge authority, product manifest mismatch, count mismatch, redaction mismatch, forbidden input fields, raw path/URL/value exposure, browser-owned content, or package-row mutation attempts.

- Does this selection implement package review? Recommended answer: no. It freezes the package-review preview runtime contract only.
