This selection admits the next runtime needed to carry SEC HTML/iXBRL fact authority into Layer 3 material authority. The future bridge should reload a server-issued fact-authority receipt, revalidate the parser/source-artifact chain, reconstruct ordered inline XBRL fact values from the retained primary document, and materialize a dataset version under `sec_edgar_html_inline_xbrl_fact_material_units_v1`. Operator responses, status projections, and Gate B payload surfaces must expose only redacted counts, hashes, dataset ids, and provenance, not raw filing URLs, local paths, artifact bytes, or raw fact values.

The selection intentionally preserves the existing HTML/iXBRL narrative/table material bridge and downstream proof. It does not admit taxonomy network resolution, SEC Company Facts, standalone XML XBRL, financial-statement semantics, fact-to-statement classification, browser-submitted HTML, live SEC fetch, source expansion, provider writes, connector dispatch, RAG/model runtime, full mockup activation, browser storage authority, or frontend durable authority.

## Coherence Check

- Should this bridge be evidence-only? Recommended answer: no. The governed end state needs fact-derived Layer 3 analysis material, so the selected bridge should materialize fact rows as server-owned dataset material while keeping operator projections redacted.
- Should the bridge reuse the existing narrative/table material bridge? Recommended answer: no. It should preserve that bridge unchanged and introduce a separate fact material contract.
- Can the bridge assign statement semantics or resolve taxonomies? Recommended answer: no. Fact identity, value, order, context/unit hashes, and table anchors are enough for this slice.
