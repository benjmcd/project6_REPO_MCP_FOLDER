This freeze selects the next SEC EDGAR runtime slice: a server-owned real-filing acquisition connector that can build a bounded validation corpus from public SEC examples before any broader parser or product expansion. The runtime should reuse the current gated SEC complete-submission text source-artifact acquisition client and its User-Agent, network-enable, rate, timeout, max-byte, cache, and CI fake-client boundaries. Creating a separate SEC network stack, rate limiter, cache root, or parser path would be tech debt unless a current-main-confirmed blocker proves reuse impossible.

The future connector may discover filings through server-owned SEC submissions metadata for validated or allowlisted CIK references, then acquire supported complete-submission text artifacts through the existing source-artifact path. It must record deterministic connector receipts, source-family classification, per-example expected support status, artifact hashes, diagnostics, and redacted operator status. The first validation corpus should include real 10-K, 10-Q, and 8-K examples, plus modern HTML/iXBRL, table-heavy, and multi-document/exhibit-like filings where feasible.

The first runtime must not claim full SEC support. HTML/iXBRL/XML filings must be classified, blocked, or degraded with diagnostics until a separate parser/source-family slice admits handling them. Candidate B remains limited to SEC-related PDF/page/visual evidence roles and must not become the general SEC filing parser. Supported complete-submission text examples should flow through the existing SEC text/table authority, DatasetVersion/material bridge where applicable, Layer 3 downstream proof/status, and operator inspection.
