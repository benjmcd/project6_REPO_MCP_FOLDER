## Current Live Boundary

Current main admits only these package lifecycle runtimes beyond ordinary package construction/submit:

- `package_supersession_preview_only`: read-only preview, no database writes and no filesystem writes.
- `replacement_package_set_authority`: durable metadata authority for a replacement package set, no replacement `L3OutputPackage` rows and no package payload writes.
- `package_supersession_commit_entry`: immutable lineage record from source package set to replacement package-set authority, no package row mutation and no package payload writes.

The current replacement package-set authority records `replacement_payload_refs` and `replacement_payload_hashes` as metadata. It validates shape, hash basis, no source-ref reuse, idempotency, and existing source-package authority. It does not prove the replacement payload refs exist, were generated by a repo-owned owner service, are readable, or hash to the claimed payload hashes.

## Decision

The next package lifecycle prerequisite is narrowed to exactly this future authority boundary:

- selected_future_package_lifecycle_mode: `replacement_package_artifact_authority_only`

This is not live runtime. It is the minimum future gate before any replacement package row creation, payload write, package reconstruction, or rendered package mutation control can be considered.

The future boundary must prove replacement package artifacts are server-owned or server-verified immutable artifacts before `replacement_package_set_authority` can be treated as evidence of reconstructable package content.

## Why This Outranks Broad Mutation

Broad package mutation/reconstruction would be an overclaim today because current live authority can only point at replacement refs and hashes. It cannot prove replacement payload bytes are present, generated, immutable, or bound to an owner service.

Freezing replacement artifact authority first reduces risk because it preserves the existing immutable source package rows and payloads while specifying the missing proof needed for any later package reconstruction lane.

## Future Runtime Shape

A later implementation-entry freeze may admit only one of these options:

- `replacement_package_artifact_manifest_only`: record a server-verified immutable artifact manifest for replacement package payload refs and hashes, without creating `L3OutputPackage` rows.
- `replacement_package_artifact_generation_only`: generate replacement package payload files through a named owner service in a separate immutable namespace, without updating or deleting existing package rows.
- `replacement_package_namespace_rows`: create replacement package rows only after a separate namespace model/migration preserves the existing `uq_l3_output_package_session_kind` authority for source packages.

This document selects no runtime option by itself. It blocks implementation until a later freeze chooses exactly one option.

## Required Future Authority

A later implementation-entry freeze must specify:

- exact owner service for replacement artifact generation or verification;
- exact artifact namespace and path/ref policy;
- exact payload hash algorithm and canonical byte basis;
- exact relation between replacement artifact authority and `L3ReplacementPackageSetAuthority`;
- exact relation between replacement artifact authority and `L3PackageSupersessionCommit`;
- whether the future route records a manifest only, generates payload files, or creates namespaced package rows;
- idempotency and concurrency behavior for duplicate replacement artifact requests;
- stale source package, stale replacement set, stale lineage, stale payload ref, and stale payload hash behavior;
- retention and cleanup expectations without deleting or mutating existing source package payloads;
- response-safe receipt schema;
- negative proof that package rows, source payloads, handoff/export state, connector records, provider URLs, source classes, qualitative execution, and mockup behavior are unchanged.

## Positive Invariants

The next runtime slice is acceptable only if:

- broad `package_mutation_reconstruction` remains deferred until replacement artifact authority exists;
- existing `L3OutputPackage` rows remain immutable source authority;
- existing package payload files remain immutable source authority;
- replacement artifact authority lives in a separate namespace from source package rows and payloads;
- replacement payload refs and hashes are server-generated or server-verified before use as package-set authority;
- package supersession commit remains lineage-only until a later freeze explicitly admits a stronger package lifecycle action;
- `replacement_package_set_authority` remains metadata-only and does not become artifact generation by implication;
- any future response exposes only response-safe refs, hashes, schema ids, status, and next actions.

## Stop Conditions

Stop before implementation if the intended change requires:

- accepting edited package bytes or replacement payload content from the browser;
- weakening `uq_l3_output_package_session_kind`;
- creating replacement package rows without a separate package namespace design;
- mutating existing `L3OutputPackage` rows;
- rewriting, deleting, or reconstructing existing package payload files;
- using `replacement_package_set_authority` metadata as proof that replacement payload bytes exist;
- dispatching to connectors or destinations;
- creating provider/public URLs;
- widening source/upload/local-directory/RAG/vector inputs;
- broad qualitative, hybrid, or RAG execution;
- full mockup activation;
- authentication/security work while that lane remains deferred.
