This freeze selects the next governed SEC HTML/iXBRL package lifecycle slice. The future runtime should record an explicit operator package-review decision over an existing package-construction receipt and produce a review-submit receipt that can later gate handoff/export.

The selected runtime must not mutate package payload artifacts, prepare handoff/export, deliver artifacts, fetch SEC content, reparse HTML/iXBRL, reconstruct raw fact values, resolve taxonomies, call SEC CompanyFacts, process standalone XML/XBRL, broaden parser/source scope, dispatch connectors, write provider objects, run RAG/model logic, activate full mockup behavior, or create browser-held durable authority.

## Runtime Requirements

1. Load and validate an existing package-construction receipt by id plus expected receipt hash.
2. Revalidate package payload manifest, payload order, package-review preview, downstream product, statement-classification, fact-authority, fact-material bridge, review-readiness, and redaction hashes.
3. Accept only a bounded review decision: `approved`, `changes_requested`, `rejected`, or `blocked`; require notes for non-approved decisions.
4. Record an append-only package-review submit receipt and redacted review decision state without changing package payload artifacts.
5. Preserve package payload order, product group order, table-anchor order, unknown diagnostic order, and decision order by hash.
6. Return only redacted status: decision state, notes presence/hash, payload hashes, readiness, redaction metadata, authority hashes, and next lifecycle state.
7. Fail closed on stale authority, missing construction/payload/preview/product/classification/fact/bridge authority, hash mismatch, duplicate conflicting submit, missing notes for non-approved decisions, forbidden input fields, raw path/URL/value exposure, browser-owned content, or handoff/export/delivery mutation attempts.

## Coherence Check

- Does this selection implement package-review submit? Recommended answer: no. It freezes the package-review submit runtime contract only.
- Does this prepare handoff/export or delivery? Recommended answer: no. Those remain separate future slices after approved review-submit authority exists.
- Why is this the next slice? Recommended answer: current main has package construction authority, and explicit review-submit is the smallest lifecycle step needed before handoff/export, delivery, and final operator inspection.
