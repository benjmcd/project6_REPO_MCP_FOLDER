The runtime bridges a ready SEC EDGAR text-table authority envelope into a redacted Layer 3 material-preview/Gate B authority binding. It validates the ready envelope through `layer3.sec_edgar_text_table_authority_envelope_validation.v1`, binds the envelope hash and materialization receipt to the selected DatasetVersion, invokes the existing `dataset_version` material-preview path internally, redacts raw source/storage/diagnostic refs, computes a bridge-owned `material_preview_hash`, and returns a Gate B decision payload accepted by the existing Gate B decision API.

The bridge does not itself commit Gate B. It returns the bounded Gate B payload so existing Gate B idempotency, material-preview hash, decision-manifest, session, and material-snapshot authority remain the downstream committing surface.

## Coherence Check

- Does this make raw SEC EDGAR DatasetVersion ids sufficient by themselves? Recommended answer: no. The bridge requires a ready envelope hash and returns `direct_unbridged_sec_edgar_dataset_version_material_authority_admitted: false`.
- Does this add SEC fetch or parser behavior? Recommended answer: no. It reads existing DatasetVersion/provenance authority only through the authority-envelope runtime and existing material preview.
- Does this expose raw paths or raw artifact refs? Recommended answer: no. The returned material candidate and Gate B decision basis are redacted and the tests assert the fixture raw root and temporary storage path are absent.
- What comes next? Recommended answer: select `sec_edgar_text_table_downstream_layer3_proof_selection_v1` before proving SEC EDGAR-derived material through retrieval/context, analysis, package/review, handoff/export, delivery/status, and operator inspection.
