## Escalation rule if a forbidden-touch surface appears necessary

If the write-enabled session concludes that a forbidden-touch or not-established surface is required, it must stop immediately and escalate back to planning before editing.

Minimum escalation packet:
1. exact blocked path
2. exact reason the current allowed-touch set was insufficient
3. exact Phase 1A objective that cannot be met otherwise
4. exact proof obligation that would remain unmet
5. whether the need comes from a real contract mismatch, a route/UI widening attempt, a runtime-boundary issue, or an unestablished new truth surface
