### Recovery and reconciliation policy

`tools/dual_live_recovery.py` is a preservation-first, offline-only operator
tool. It has no connector, transport, socket, request, subprocess, retry, DML,
delete, source-relocation, or repair capability. Its only internal move is the
existing raw-storage primitive's anchored, atomic stage-to-final publication of
the new poison marker. It refuses unless:

- campaign identity is canonical UUID4 plus lowercase SHA-256 fingerprint;
- all source paths are absolute, local, existing, non-reparse paths;
- `CONNECTOR_LIVE_EGRESS_ENABLED` is explicitly false;
- credential-, token-, key-, grant-, definition-, and campaign-authority
  environment values are absent;
- the deterministic capture directory exists and is unsealed; `poison` requires
  no existing poison/tombstone, while `inspect` and `archive` require a canonical
  poison marker for the same campaign and fingerprint.

Producer quiescence is an external, mandatory operator precondition; the tool
does not acquire the production lock, inspect a job object, or otherwise enforce
or prove it. The operator must first preserve independent process/job/lock
evidence that the producer is gone. Source hashes detect drift during an action,
not an atomic snapshot and not mutate-and-restore.

The marker contract is `project6.dual_live_recovery_marker.v1` with exact keys
`campaign_id`, `campaign_fingerprint`, `marker_kind`, `reason_code`, and
`schema_id`. `marker_kind=poison` is required; a matching `tombstone` is
optional but retained when present.

The tested operator entry point publishes the marker with the repository's
anchored, parent-identity-bound, atomic strict-new raw-storage primitive. It
checks lexical and resolved reparse components, fsyncs and rehashes the staged
bytes before exposure, and refuses a sealed campaign, an existing
poison/tombstone/stage, unsafe paths, credentials, non-offline configuration, or
an invalid/overlong reason code:

```powershell
$env:CONNECTOR_LIVE_EGRESS_ENABLED='false'
& 'C:\Users\<operator>\AppData\Local\Programs\Python\Python312\python.exe' -I -B .\tools\dual_live_recovery.py poison --campaign-id <uuid4> --campaign-fingerprint <sha256> --database-path <absolute-db> --storage-root <absolute-storage> --evidence-root <absolute-evidence> --reason-code phase_b_interrupted
```

The real killed-cell test executes this production `poison` implementation,
then `inspect`, then `archive`; marker creation is not delegated to a test-only
helper.

Direct `inspect` opens the database with SQLite immutable read-only semantics and
refuses any nonempty WAL, SHM, or rollback journal before SQLite opens it. For a
WAL-backed killed campaign, `archive` performs this order instead:

1. hash the original DB family, storage root, and evidence root;
2. exclusively copy and verify the exact raw DB family and all evidence;
3. build a separate permanent inspection clone under the archive, omitting the
   original SHM so SQLite may rebuild only the clone's SHM;
4. query the clone in read-only/query-only mode for integrity, campaign-scoped
   Layer-3 rows, and foreign-key orphans;
5. re-hash the originals and raw archive and fail on any drift;
6. publish a canonical, no-overwrite manifest that distinguishes raw evidence
   from derived inspection files.

The recovery disposition is archive/abandon, not repair:

- original database, storage, capture directory, poison marker, and consumption
  state remain in place;
- the exact raw archive plus derived inventory is permanent evidence;
- orphaned Layer-3 rows are inventoried, never deleted or rewritten;
- the abandoned DB/storage roots must be removed from active configuration by an
  operator configuration switch, not by row cleanup;
- any later real acquisition needs a new definition, campaign ID/fingerprint,
  grants, and separate owner authorization. The failed campaign is never reused.

A nonempty hot rollback journal remains `STOP/UNCLASSIFIED`; this offline tool
does not claim a consistent snapshot of a live producer. Pre/post hashes detect
drift but cannot prove an atomic snapshot or detect mutate-and-restore. If the
poison action is interrupted before atomic publication, a stage-only artifact
may remain but a partial final `poison.json` is never exposed. The stage is
retained, blocks replay, and requires explicit operator adjudication; the tool
does not repair, delete, or overwrite it. If the archive process is interrupted,
a partial no-overwrite destination may remain; it is retained as evidence and
blocks reuse of that archive directory. The tool does not delete, resume, or
silently replace it.

## G2-P5: credential containment and HTTP execution

temporary live-window switch and supersedes the older functional HTTP-route
expectation; re-enabling it would be a separately reviewed substrate change.

**Required intended-safety statement:** evaluator and gate refusal of
HTTP-driven, partial, duplicate, foreign, incorrectly ordered, or incompletely
bound runs is intended safety behavior for the shared-executor seam, not an
incidental availability defect.

### Provisioning-boundary check procedure

Before any future live window:

1. Stop the long-lived FastAPI process. Clearing parent environment values is
   insufficient because imported settings may be cached.
2. Treat process environment plus the startup working directory's `.env` as one
   effective configuration source. Hash/freeze both for the launch; a clean OS
   environment alone is insufficient because `Settings()` loads `.env`.
3. Launch FastAPI through an in-process, pre-bind assertion over the same
   singleton `app.core.config.settings` that the server will use. It must fail
   before binding unless live and exclusive flags are false; the NRC key is
   empty; and all of these are absent/`None`:
   `CONNECTOR_CAMPAIGN_DEFINITION_PATH`,
   `CONNECTOR_CAMPAIGN_DEFINITION_SHA256`,
   `CONNECTOR_CAMPAIGN_EVIDENCE_ROOT`,
   `CONNECTOR_CAMPAIGN_EVIDENCE_INDEX_PATH`,
   `CONNECTOR_CAMPAIGN_EVIDENCE_INDEX_SHA256`,
   `CONNECTOR_SCIENCEBASE_GRANT_PATH`,
   `CONNECTOR_SCIENCEBASE_GRANT_SHA256`,
   `CONNECTOR_NRC_APS_GRANT_PATH`, and
   `CONNECTOR_NRC_APS_GRANT_SHA256`. The assertion reports presence booleans
   only, never values. The NRC field/alias checked is
   `settings.nrc_adams_subscription_key` /
   `NRC_ADAMS_APS_SUBSCRIPTION_KEY`.
4. Exercise the authenticated HTTP execute route and separately require the
   deterministic disabled `409` before all strict service seams. Route refusal
   does not prove the effective Settings check in step 3.
5. Construct Phase A only through the owned CLI controller. Only its short-lived
   acquisition child may receive live enablement, the NRC key, and current
   definition/grant paths and hashes.
6. Require Phase-A child quiescence and authority clearing before Phase B. The
   Phase-B child receives `CONNECTOR_LIVE_EGRESS_ENABLED=false`, no key, and no
   current definition/grant paths or hashes. It intentionally retains the
   protected historical evidence root/index path/index SHA coordinates needed
   for offline evaluation; those coordinates are non-authorizing history, not
   current acquisition authority.
7. Re-run the offline environment-split, pre-body authorization, route-refusal,
   evaluator census, and gate suites. Any secret in FastAPI or Phase B is STOP.
