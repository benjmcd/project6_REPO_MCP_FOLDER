## Root cause and correction

The failing test executes two sequential A/B controller runs in one isolated
Python process: four real child lifecycles total. Each phase retains its own
10-second fail-closed deadline, and each real child boot separately retains the
hard production 5.0-second deadline. The outer 30-second test watchdog also had
to cover interpreter startup, imports, handle accounting, cleanup, two garbage
collections, and final serialization. It was therefore narrower than the valid
nested workload and could erase the inner diagnostic with `TimeoutExpired`.

R5 raises only that outer test watchdog from 30 to 90 seconds. Ninety seconds
covers the formal 60-second four-phase/four-boot envelope plus harness overhead
while retaining a bounded hard-hang cap. It does not change either the inner
10-second phase deadline or the production 5.0-second boot deadline. The two
runs remain in one process so their handle/thread release and identity
disjointness assertions remain intact.
