The correction is test/CI-only:

1. `backend/tests/test_dual_eval.py` moves intact to the existing
   `dual-gate-windows` job. It remains a separate serial Python process, so its
   process-lifetime spawn guard cannot contaminate the root proof suite.
2. The Ubuntu `backend-layer3-api` job returns to being a shard-result
   aggregator. No evaluator path rule is relaxed and no failure-shaped skip
   list is introduced.
3. The coverage contract binds the evaluator to `windows-latest`, the exact
   30-minute job, the serial flags, and the shared dependency lock; it also
   rejects a duplicate evaluator command in the Ubuntu aggregator.
4. The PowerShell direct-launch test uses exact Python 3.12, matching both the
   repository launcher default and the job's provisioned dependency runtime.
5. The blocked-write race gives cold child census up to 30 seconds and starts
   the 50-millisecond failure window only after the writer thread reaches the
   intercepted `WriteFile`. A deterministic 100-millisecond writer-scheduling
   delay reproduces the old failure and proves the corrected ordering.
