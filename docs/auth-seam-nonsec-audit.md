## Scope Resolution

This audit uses the narrow milestone scope: non-SEC Layer 3 routes mounted under `/api/v1/layer3` from `backend/app/api/layer3/__init__.py`, `handoff.py`, `package.py`, `operator_identity.py`, and `source_ingestion.py`, plus the NRC APS review API mounted under `/api/v1/review/nrc-aps`. The broader adjacent scope would include legacy dataset/connector routes in `backend/app/api/router.py` and SEC-adjacent `source_sec_edgar.py` / `sec_xbrl.py`; those are deliberately excluded here because the milestone is non-SEC and the handoff forbids SEC route/service/network changes. The existing route-authorization doc already treats legacy and SEC-family coverage separately.

Canonical mount evidence: `backend/app/api/router.py:100-102` creates the API router and mounts NRC APS at `/review/nrc-aps` and Layer 3 at `/layer3`; `backend/main.py:457` mounts that router at `settings.api_prefix`. Canonical auth helper evidence: Layer 3 shared routes delegate through `_route_level_operator_identity` in `backend/app/api/layer3/_shared.py:3892-3896`, while NRC APS uses its module-local helper in `backend/app/api/review_nrc_aps.py:71-76`.

## Behavior Classes

- `G-read`: route-level operator identity is wired with `access="read"`. Under `AUTH_OWNER=none`, the local single-operator profile remains inert and records derived identity without blocking. Under the default `identity_presence` authorization mode, role derivation/cap enforcement is inert. Under proxy/role-enforcing mode, missing identity/workspace/role authority fails closed before route body logic.
- `G-write`: same seam and default behavior as `G-read`, but role-enforcing proxy mode admits only owner role for write access.
- `P-public`: intentionally public metadata route. No route-level identity is recorded by the in-route seam, and the route must remain open even when proxy role enforcement is configured.

Source-backed policy context: `docs/layer3-route-authorization.md:56-61` defines `identity_presence` as the default inert mode and `role_enforcing` as opt-in; `docs/layer3-route-authorization.md:66-70` preserves `AUTH_OWNER=none` as a local single-operator owner profile; `docs/layer3-route-authorization.md:125-135` lists the explicit public metadata/fail-soft surfaces.

## Regression Hardening

New additive tests live in `backend/tests/test_auth_seam_nonsec_audit.py` and are intentionally limited to non-SEC route files plus NRC APS runtime probes:

- Static inventory guard: asserts the in-scope route count, per-file route/gated/public counts, public metadata exemptions, read/write access-class totals, and all 23 NRC APS routes as read-only GET seams.
- Public metadata runtime guard: asserts `/api/v1/layer3/bootstrap`, `/api/v1/layer3/readiness`, and `/api/v1/layer3/authority-matrix` remain non-auth-blocked even under proxy `role_enforcing` mode.
- NRC APS runtime probes: assert `AUTH_OWNER=none` remains inert, `identity_presence` ignores a missing roles header, trusted proxy without identity fails closed, role-enforcing without roles fails closed, and auditor role is admitted for the read route.

Existing route-auth tests still provide the broader policy matrix and representative Layer 3 handoff/package/source-ingestion probes in `backend/tests/test_layer3_route_authorization_policy.py` and `backend/tests/test_layer3_operator_identity_e2e.py`.

## Recommendation

Do not change enforcement behavior in this milestone. The current non-SEC Layer 3 + NRC APS source state is coherent for Tier-1 audit/test hardening: gated routes are wired with explicit `read`/`write` access classes, and the three ungated Layer 3 core routes are documented public metadata exemptions.

The next Tier-2 decision, if selected later, is policy/operator-workflow work rather than a route-local patch: decide whether nonlocal deployments must require `role_enforcing`, and whether `egress_write` / `decision_write` access classes should split the current `write` class for export and decision routes. That would need proxy roles-header readiness, docs/runbook updates, and a separate risk review. Reverse-proxy lockdown of public metadata, `/docs`, or `/openapi.json` should also stay deployment-owned unless a later in-app auth design is explicitly selected.
